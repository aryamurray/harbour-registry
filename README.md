# Harbour registry

A Harbour registry: a git repository in Harbour's registry layout, holding real C and
C++ packages as pins and patches (no upstream source is vendored). It is generated by
`tools/registry-from-shims/make_registry.py` in the harbour repository, never hand-edited.

Some packages need host tools on `PATH` (OpenSSL needs `perl`). Redis is POSIX only.

## Use it

In Harbour's global config (`~/.harbour/config.toml`; a non-empty `registries` list REPLACES
the built-in registries, so keep those after it):

```toml
[[registries]]
name = "personal"
url = "https://github.com/<owner>/<repo>"   # or ssh://git@github.com/<owner>/<repo>.git
priority = -10                              # lower wins
```

Harbour fetches with your system `git`, so a private repo works with whatever your git is
already set up for (credential helper, `gh auth setup-git`, ssh keys and ssh config).

## Layout

`index/<letter>/<name>.idx` is the tier-1 index (one JSON line per version: dependencies,
checksum, license, shim path). `index/<letter>/<name>/<version>.toml` is the tier-2 shim (the
source pin: git url and rev, or tarball url, sha256 and strip_prefix; its patches).
`<version>.patch` adds the package's `Harbour.toml`, plus any overlay file. `.gitattributes`
carries `*.patch -text` so line-ending conversion cannot change a patch's bytes (Harbour
hashes them exactly): do not remove it.

## Regenerate and verify

From the harbour repository, into a FRESH directory:

```sh
python3 -I tools/registry-from-shims/make_registry.py /path/to/new-registry target/release/harbour     --cache /path/to/cache --tarball zlib
```

Then replace this repository's tree with the output as an ordinary commit (do not rewrite
history), and check it: point a scratch Harbour config at a copy with `url = "file://..."` and
`harbour add <package>` then build a small consumer for each package. To add a package, add a
row to `PACKAGES` (and `TARBALLS`) in `make_registry.py` and put its manifest next to the others.
